## Implemented

- iOS runtime downloads now have explicit cancellation, attempt identity and
  descriptor checks, retry isolation, interrupted-task recovery, integrity
  validation and safe corrupt-file cleanup. Background-session completion is
  delivered on the main thread after events drain. Recovery waits for protected
  journal data; downloads completed while it is locked are staged with a receipt
  and validated after unlock or restart. Late callbacks cannot claim a new attempt.
- Shared UI exposes cancellation and its result. Android reports optional runtime
  installation/cancellation as unavailable. A downloaded file never changes an
  optional CLI's execution capability to available.
- Pi uses the official, separately attributed SVG. Runtime rows align its icon
  with the other product icons and the custom-script row.
- Default-model settings and the conversation picker expose Add / custom model.
  Both reuse the existing provider editor and registry persistence. Returning
  preserves chat/configuration drafts. A deleted staged selection shows an error
  and keeps the picker open; saving a catalog does not replace historical models.
- Source preflight recognizes the reviewed GPUI vendor patches and Pi asset,
  while checking package identity/version and preserving path/pinning checks.
  Android Build Tools is pinned to the documented 36.0.0. iOS check deployment
  variables are scoped to Rust target checks, avoiding macOS host-test leakage.
- DSH/zcode distribution evidence and the Android installation boundary are
  recorded in [runtime-engine-installation.md](runtime-engine-installation.md).
  Neither has been given an unverified download URL.

## Mobile interaction gates

- iPhone 17 Pro / iOS 26.5 simulator: both custom-model entries and the aligned Pi
  logo were observed. The synthetic unsent draft `20261106` survived entering
  the provider editor and returning. The long model editor's manual/save fields
  were below the viewport; CUA endpoint-only drags did not move the content.
  An isolated XCTest continuous touch gesture then scrolled both fields fully
  into view with the header fixed, confirming that native touch scrolling works.
  Through the native editor, synthetic ID `rish-p0-smoke-20261106` / display name
  `Rish P0 QA` was saved, appeared in the picker, and was selected with Done.
  The chat showed the selected name and the original unsent `20261106` draft;
  the latter was also read from the actual native text field, without reinsertion.
  No credentials, live model discovery or model requests were used. The gesture
  tests, result bundles and screenshots are in `ios-touch-qa/`, including
  `saved-model-picker.png` and `selected-model-chat.png`. Desktop scroll tests pass
  for empty and 24-model catalogs at phone portrait/landscape and tablet sizes.
  The final app was then installed over the existing QA app and relaunched;
  its installed executable hash matches the artifact below, and `Rish P0 QA`
  remained selected (`ios-final-build-launch.png`). The unsent input was empty
  after this force-terminate/install cycle: draft preservation is verified within
  the editing/selection flow, not across process restart. Add restart recovery to
  the outstanding draft acceptance checks.
- Android API 33 arm64 emulator: launch succeeded, but opening the model picker
  produced persistent striped rendering with both host GPU and SwiftShader.
  Both selected the Vulkan backend. No crash is required for this visual failure;
  the existing renderer smoke test only checks initialization and nonempty PNGs.
  A cold boot with `-gpu host -feature -Vulkan` exposed a GLES adapter, but device
  creation failed because its `max_compute_workgroups_per_dimension` was 0 while
  the renderer requested 65535. This is a verified fallback limitation, not a
  solution to the Vulkan corruption. No renderer code was changed; Android
  visual acceptance is not passed. See `android-gles-logcat.txt` and the three
  emulator logs/screenshots. The temporary read-only emulator was stopped.
- iPad, physical devices, live-provider discovery, account-switching and Android
  manual-add/select flows remain unverified in this pass.
