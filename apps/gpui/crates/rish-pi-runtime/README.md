# Embedded Pi bundle provenance

`vendor/pi-agent-core-1.4.0.js` contains the actual upstream Pi Agent Core and
the Pi AI utilities used by it, bundled for the embedded QuickJS runtime.
The source entry is `js/bundle-entry.mjs`; `js/platform.js` and `js/bridge.js`
are separate host integration sources and are not part of this upstream bundle.

The exact inputs are `@earendil-works/pi-agent-core@1.4.0`,
`@earendil-works/pi-ai@1.4.0`, `typebox@1.3.27`, and the build tool
`esbuild@0.25.12`. `package-lock.json` pins the complete dependency graph,
including npm tarball URLs and integrity values. The upstream Pi repository
is <https://github.com/earendil-works/pi>, with Agent Core under `packages/agent`.
The bundle is generated from the published npm artifacts, not an unrecorded
Git checkout.

From this directory, with Node.js 22.19.0 or newer and npm:

```sh
npm ci
npm run check:bundle
```

`npm run bundle` regenerates the vendored file using the same build options:
browser platform, ES2022 target, IIFE output, bundling, and minification.
Both commands verify package versions, require a single output without
external imports, check that only the three listed upstream packages
contribute code, and require the reviewed digest in `vendor/provenance.json`.
The check command also compares the generated bytes with the vendored file.
For an intentional dependency or source update, review the output and update
the provenance digest explicitly rather than bypassing this comparison.

The original bundle and the reproduced bundle are both 170,309 bytes with
SHA-256 `6968a15501790f43e7e9c75cfee14d04b7954a2da190d34284325dc1b777e6e1`.
Reproduction was checked with Node.js 26.0.0, npm 11.12.1, and esbuild 0.25.12
on macOS arm64. `npm ci --offline` can be used when these pinned tarballs
already exist in the local npm cache. Rust builds consume the checked-in
bundle and do not invoke npm or download JavaScript dependencies.

The npm dependency graph contains provider SDKs because Pi AI declares them.
Esbuild's recorded contribution check confirms that those SDKs, the Pi CLI,
and Pi telemetry contribute no code to this bundle. Provider requests and
native tool execution remain separate host responsibilities.

Preserve `vendor/LICENSE-pi-MIT` for Pi Agent Core and Pi AI and
`vendor/LICENSE-typebox-MIT` for TypeBox when redistributing the bundle.
Esbuild is a build dependency and is not included in the generated artifact.

## Host contract

The `engine` feature embeds this bundle in QuickJS through `rquickjs` 0.12.1.
It does not start a CLI, Node.js, a subprocess, or a remote runtime. The Rust
actor owns the interpreter on its existing assistant thread. iOS and Android
enable `bindgen` because upstream ships desktop bindings only; their build
environment must supply the target SDK headers to Clang. The engine has no JIT.

Pi emits a model intent or a tool intent. A tool intent is an opaque native
capability: round ID/index, call ID, tool name, and arguments digest. The actor
allows an effect only when that intent matches the existing native command.
Native CAS, approval, WAL, and receipt validation remain authoritative. Pi never
receives private tool arguments or output; it receives the genuine committed
receipt. Provider bindings, models, and credentials belong to the host, not the
runtime definition.

Restart restores Pi at the validated current round frontier, using the native
transcript reference. It consumes only the current committed batch and its
receipts, in Pi's intent order. Earlier batches are not present in the public
journal, so the host does not fabricate historical tool calls or replay their
effects. Existing run records without a runtime definition keep the explicit
legacy controller; every newly claimed run freezes its selected definition.

## Custom script ABI 1

Custom runtime scripts extend Pi through two optional synchronous policy hooks:

```js
{
  beforeModel(context) {
    return { allow: true };
  },
  beforeTool(context) {
    return context.name === "write_file"
      ? { stop: "Review the proposed write first" }
      : { allow: true };
  }
}
```

The source is an object expression, limited to 32 KiB and frozen with its SHA-256
and ABI/Pi version in each run. Each hook runs in a fresh realm with no ambient
filesystem, network, process, module-loading, or host API. Hooks must return
exactly `{allow:true}` or `{stop:"reason"}`. Promises, exceptions, malformed
results, unsupported versions, and resource exhaustion fail closed. A stop or
error persists a stop intent and enters the native cancellation path; it never
falls back to another runtime.

Both hooks receive `model_id`, `provider_id`, `attempt_id`, `round_id`, and
`round_index`. `beforeTool` also receives `call_id`, `name`, `arguments_sha256`,
`access`, and `approval_decision`. Neither hook receives credentials, raw tool
arguments, private output, or permission to perform effects. The interpreter
uses a 64 MiB heap limit and bounded execution/job budgets; hook evaluation is
limited to 100 ms per call.
